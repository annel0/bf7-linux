# BF7: аппаратный UART и материалы по плате

Дата проверки: 2026-08-23.

## Краткий итог

Для BF7 найдены точные публичные фотографии основной платы без экранов и
подтверждено существование отдельного `TECNO BF7 Service Manual.pdf`. Однако
свободно доступной схемы или boardview с однозначно подписанными
`UART_TX/UART_RX/GND` пока не найдено. По одним FCC-фотографиям выбирать точки
и паяться нельзя: на плате много внешне одинаковых тестовых площадок.

Аппаратный UART имеет смысл: текущая программная диагностика видит только
посмертный `AEE_EXP_TYPE_LK_CRASH`, но не PC/stack. Последние строки Preloader,
LK и раннего kernel console позволили бы локализовать сбой `fastboot boot`.

- Устройство: TECNO BF7, FCC ID `2ADYY-BF7`.
- Страница внутренних фотографий:
  <https://fccid.io/2ADYY-BF7/Internal-Photos/Internal-photos-6598307>

- PDF 2: <https://fccid.io/2ADYY-BF7/Internal-Photos/Internal-photos-6230673.pdf>

Оба PDF содержат 12 страниц и показывают обе стороны основной платы, в том
числе без металлических экранов. Разрешение отдельных PCB-фото — 1048x786.
Маркировка UART на них не читается. На открытых участках видны группы золотых
test-point, но их назначение по фотографии не доказано.

В FCC-пакете есть metadata-запись схемы размером около 1.6 MB, но TECNO
официально запросила постоянную конфиденциальность для schematics, block
diagram, operation description, tune-up и BOM. Поэтому FCC даёт фотографии,
но не выдаёт саму схему:
<https://device.report/m/afa0f763b1089ea5ffeb7da1ec7c8ba72abf3db5947381ea30eb09907f67bbcf.pdf>

### Дополнительное подтверждение SoC UART

В опубликованном опыте восстановления именно Pop 7 Pro BF7 лог MTKClient
показывает MMIO base `Uart: 0x11002000` для MT6761:
<https://www.hovatek.com/blog/my-experience-unbricking-a-dead-boot-tecno-pop-7-pro-bf7/>

Это подтверждает UART-контроллер SoC, но не раскрывает физические TX/RX
test-point на плате. Материал не является разрешением использовать mtkclient;
в проекте он по-прежнему запрещён без отдельного явного согласования.

## Уже известные параметры консоли

В рабочем LK log зафиксирован bootarg:

```text
console=tty0 console=ttyS0,921600n1
```

Следовательно, основной кандидат для kernel console — UART0, 921600 baud,
8 data bits, no parity, 1 stop bit. Для ранних Preloader/LK сообщений также
стоит пассивно проверить 115200 baud: разные стадии могут использовать разные
скорости.

В той же командной строке последовательно присутствуют:

```text
mtk_printk_ctrl.disable_uart=0 mtk_printk_ctrl.disable_uart=1
```

Последнее значение может отключать kernel printk на UART. Это не отменяет
полезность пассивного захвата Preloader/LK и не доказывает отсутствие сигнала
на площадке.

## Электрическая безопасность

Уровень логики пока не измерен. Для MediaTek-плат этого класса вероятен UART
1.8 V, но это гипотеза до измерения. Подключать 3.3 V или 5 V TX адаптера к
неизвестной площадке запрещено.

Безопасная последовательность поиска:

1. Сделать резкие макрофото обеих сторон именно нашей ревизии платы, с
   читаемой маркировкой PCB и всеми test-point.
2. На полностью обесточенной плате найти GND прозвонкой до металлического
   экрана или минуса аккумулятора.
3. При загрузке наблюдать остальные площадки только высокоомным осциллографом
   или logic analyzer, рассчитанным на 1.8 V. Искать burst активности сразу
   после подачи питания.
4. Подтвердить idle level и амплитуду. Не считать площадку UART только по
   наличию импульсов.
5. Для первого захвата соединять только общий GND и `RX` анализатора с
   предполагаемым `TX` телефона. Ничего не передавать в телефон.
6. Сначала пробовать декодирование 921600 8N1, затем 115200 8N1.
7. `TX` адаптера подключать к `RX` телефона только после подтверждения pinout
   и через корректный 1.8 V level shifter; для нашей задачи он пока не нужен.

Нельзя прозванивать сопротивление на запитанной плате, подавать питание на
test-point, коротить соседние площадки щупом или опираться только на pinout
другого MT6761-телефона.

## Что нужно для точной идентификации

- Макрофото своей платы с двух сторон, строго перпендикулярно, при хорошем
  рассеянном свете; отдельно — крупные кадры всех групп test-point.
- Читаемый PCB/revision code.
- Мультиметр с режимом прозвонки.
- Лучше осциллограф; допустим logic analyzer с явно подтверждённым входом
  1.8 V. Обычный USB-TTL использовать только как RX после проверки его
  входных порогов, не подключая его TX/VCC.

После этого можно составить нумерованную карту кандидатов, определить GND и
пассивно проверить TX без риска записи или изменения flash.

## Статус

- Точная плата на фотографиях: подтверждено.
- Точный service manual существует: подтверждено по каталогу, содержимое не
  получено.
- Свободный BF7 boardview/schematic: не найден.
- UART console bootarg: подтверждено (`ttyS0`, 921600 8N1).
- UART controller base: независимо подтверждено как `0x11002000` для BF7.
- Физические TX/RX test-point: не определены.
- Логический уровень: не измерен; считать потенциально 1.8 V.
