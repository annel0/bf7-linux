# mn78911 (свет + приближение, i2c-1:0x41): что делает прошивка SCP

Разбор `firmware-backup/scp/scp_a.img`, 2026-09-25. Драйвер лежит в оверлее
(адрес = смещение в scp.bin − 0x49d38; scp.bin = образ с 0x16f0, основной
образ грузится с 0x800). Таблицы переходов: свет 0x3b60c, приближение
0x3ebfc. Запись (рег, знач) — 0x3a9f0/0x3d2c4, блок — 0x3ac40/0x3cf8c.
cust: шина 0, адрес 0x41, 400 кГц. Карта регистров НЕ как у Elan EPL259x.

## Инициализация (прошивка делает её при загрузке сама)
02=02, чтение 06..07 («renvo», у нас 0x2388), 44=00, 44=02, 34=00, 34=02,
F0=8E, F4=21, пауза 5 мс, F4=20, F0=00, 02=01; [26]=00 00, [16]=00 00,
[30..33]=0, 01=8E, [14]=00 8A, [03..05]=8F 0A 9E, [52..57]=09 F4 0B B3 0F 61,
[58]=60 EA, [5A]=D0 07, [5C]=60 EA, [5E]=DC 05; для приближения ещё
[20..24]=4A 04 62 00 92.

## Пуск и стоп
0x02: 01 — стоп, 02 — пуск. 0x00: бит 0 — свет, бит 1 — приближение, 0x80 —
как у прошивки (вероятно, автоусиление). Минимальный пуск (проверено):
02=01; 00=0x81/0x82/0x83; [40..43]=88 13 7C 15; [30..33]=11 27 10 27;
[52..57]=09 F4 0B B3 0F 61; 34=00; 34=02; 44=00; 44=02; 02=02.

## Данные
- Свет: 8 байт с 0x34 — 0x34 флаги, ch0 0x36..37, ch1 0x38..39, ch2 0x3A..3B
  (младший первым). Люксы = ch1 × 300 / 1000 (калибровка по умолчанию 1000).
  В комнате днём ~134 лк.
- Приближение: флаги 0x44 (бит 3 — «ниже нижнего порога» = далеко; бит 2 —
  прерывание, после чтения 44=02), данные 0x47..0x48, ИК 0x49..0x4A. Пороги
  в чипе 5000/5500 ([40..43]); вдали ~380.

Ошибка первой попытки: 0x02 оставался 01 (чип стоял); записи в
0x11/0x12/0x1b/0xfc..0xfe по карте EPL259x для этого чипа бессмысленны.

## Проверка закатом (2026-09-25 15:30–18:49)
ch0: 730 → 577 → 521 → 189 → 104 → 57 → 18 → 8; ch1: 443 → 391 → 381 → 230 →
181 → 154 → 136 → 126. Датчик видит свет, но у ch1 «пол» ~126, поэтому
`bf7-sensor-proxy` считает люксы по ch0 × 0,18 (днём ≈ 133 лк, как формула
прошивки, в темноте ≈ 1 лк). Опыты с гаммой монитора ПК и белым экраном
самого телефона реакции не дали — свет туда просто не попадал в окошко.
