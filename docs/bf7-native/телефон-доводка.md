# Доводка телефона до конфетки

Цель, поставленная 2026-09-21 ночью: **не только композитор, а весь телефон.**
Клавиатура, Wi-Fi, Bluetooth, звук — всё, что можно. Найдено — чинить, нет —
ставить, некрасиво — исправлять, медленно — ускорять. Список живой: по мере
прохода отмечается сделанное и дописываются новые находки.

Отметки: `[x]` сделано и проверено, `[~]` сделано наполовину, `[ ]` не начато.

## Основание (сделано этой ночью)

- [x] **Обычный Wayland.** Клиенты отдают буферы через `zwp_linux_dmabuf_v1`
      вместо `android_wlegl` — правка libhybris. Работает любой композитор, не
      только наш. Доказано: `create_immed` с форматом AB24, ноль обращений к
      android_wlegl.
- [x] **Буферы показа из gralloc.** Перехват `drmGetCap` отвечает `0x3` на
      `DRM_CAP_PRIME` за pvrsrvkm. `GBM allocator with backend pvr`, ни одного
      `CREATE_DUMB`, CMA почти не тратится.
- [x] **`wl_drm` и `linux-dmabuf` живы** — фильтр расширений сужен до одного
      имени `EGL_EXT_platform_device`.
- [x] **CMA 16 → 128 МБ** (`cma=128M` в командной строке загрузки; ядро не
      пересобиралось, образ перепакован).
- [x] **Телефонный сеанс как служба** — `bf7-phosh.service`, взаимоисключающая
      с `bf7-session.service` (обычный рабочий стол).
- [x] **gnome-session** вместо голой оболочки: поднялись все службы настроек
      (яркость, звук, мультимедийные клавиши, время, клавиатура).
- [x] **Экранная клавиатура** squeekboard — входит в обязательные составляющие
      сеанса, запускается сама.
- [x] **Раскладки** us + ru заданы в `org.gnome.desktop.input-sources`.
- [x] **Обои и тёмная тема** — поставлен `gnome-backgrounds`, задана
      `prefer-dark`.
- [x] **Гашение экрана по кнопке** — демон `bf7-blank`, отдельный от
      композитора: работает под обоими сеансами, усыпляет тач (экономит 175 мА).

## Железо: чего нет

- [x] **Звук.** Динамик и микрофон работают. Нужны две вещи сразу: удерживать GPIO 151 (`extamp_gpio` из дерева устройств) высоким и поднять `AUD_CLK_BUF_Switch`, `Audio_Amp_L/R_Switch` при **работающем** потоке. Путь живёт только пока поток открыт, поэтому устройство держит PulseAudio с явными устройствами и без `suspend-on-idle`. Проверено замером: пик спектра записи ровно на 440 Гц.
      ни pulseaudio, ни pipewire не запущены. Микрофон работает.
- [x] **Wi-Fi в оболочке.** Поставлен NetworkManager, сеть перенесена из
      `wpa_supplicant` (пароль не покидал телефон). `rndis0` объявлен
      неуправляемым — иначе NetworkManager забрал бы канал связи с ПК. Значок
      сети в верхней строке появился, `wlan0: connected`.
- [x] **Bluetooth.** (Сделано: мост к виртуальному HCI, см. «Bluetooth: пройдено далеко» ниже и самопроверку.) Ядро связности поднято (`wmt_drv`, `/dev/stpwmt`,
      `/dev/wmtdetect`), но модуля `bt_drv` нет: **исходников для нашего чипа
      в донорах нет**, есть только от mt6781, а там другое поколение ядра
      связности. Нужен перенос драйвера плюс BlueZ и мост `/dev/stpbt` → HCI
      (`btattach -B /dev/stpbt -P h4`). Отдельный проект.
- [x] **Яркость.** (Сделано: модуль `bf7-backlight`, ползунок в шторке работает.) `/sys/class/backlight/` пуст: панель зарегистрирована
      светодиодом (`/sys/class/leds/lcd-backlight`, предел 255). В ядре
      `CONFIG_BACKLIGHT_LCD_SUPPORT` не задан, поэтому `gsd-power` ползунок не
      покажет. Нужна пересборка ядра плюс небольшой драйвер.
- [x] **Вибро.** Написан мост `bf7-vibrad`: заводит через uinput устройство с
      обратной связью FF_RUMBLE и на время эффекта держит светодиод мотора.
      Проверено: яркость 255 ровно на 600 мс заданного эффекта, жалоб у
      feedbackd больше нет, профиль отклика переведён в полный.
- [ ] **Передняя камера** GC05A2 — драйвера не существует нигде.
- [ ] **Вспышка** — MT6370 на плате не распаян.

- [x] **Звук больше не роняет ядро — починено 2026-09-22 12:45.**
      `mtk_pcm_copy` делал `copy_from_user` прямо в буфер DMA, а он отображён
      как память устройства (так и сказано у `word_size_align` в
      `mtk-soc-afe-control.c`) и принимает только естественно выровненные
      доступы. Ронялось по заказу:
      `aplay -D hw:0,0 -f S16_LE -r 48000 -c 2 --period-size=1021
      --buffer-size=4084 /dev/urandom` → `ESR = 0x96000061`, сбой выравнивания
      на записи, `pc : __arch_copy_from_user`.

      **Первая попытка была мимо, и это стоит помнить.** Я выровнял приёмник:
      края побайтово через `writeb`, середину обычным `copy_from_user`. Паника
      повторилась по тому же адресу, уже из моей функции. Оказалось,
      `__arch_copy_from_user` на arm64 **выравнивается по источнику**, а в
      приёмник пишет как придётся — выравнивать `dst` бессмысленно.

      Починено посредником: `copy_from_user` в обычную память, оттуда
      `memcpy_toio`, кусками по 4 КиБ. `bf7_copy_from_user_io()` в
      `sound/soc/mediatek/common_int/mtk-soc-pcm-dl1.c`.
      Проверено периодами 1021/1023/511/257/4093/129/63, форматами
      S16_LE/U8/S32_LE, моно и стерео: ни одной паники,
      `dmesg | grep -c "alignment fault"` = 0, `speaker-test` играет.

      **Запись роняла так же, только на чтении** — нашлось по подсказке
      наблюдателя, проверять надо было оба направления сразу.
      `arecord -D hw:0,1 --period-size=33 --buffer-size=133` → `ESR 0x96000021`,
      `WnR = 0`. Микрофон «работал» лишь потому, что окно узкое: неровный
      хвост короче шестнадцати байт бывает только на заворачивании кольца.

      Пара помощников переехала в `mtk-soc-afe-control.c` и закрыла все
      драйверы: `afe-control` (3 записи + 3 чтения), `pcm-dl1` (3), `pcm-dl2`,
      `pcm-hdmi` (3), `pcm-bt-dai` (3). В `dl2` **два** определения
      `dataTransfer`, собирается то, что пишет обычным `memcpy` — сперва я
      починил мёртвую ветку `#else`. Проверено записью с периодами
      7/17/33/63/129/257/511/1021/1023 и одновременной игрой в обе стороны;
      микрофон пишет живой звук, `paplay` играет, самопроверка 41/41.
