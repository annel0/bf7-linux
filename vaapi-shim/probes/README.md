# Пробы к драйверу VA-API

Маленькие программы, которыми выяснялось, что железо и чужой код на самом
деле умеют. Собирать и запускать — на телефоне.

| Проба | Что выясняет | Сборка |
| --- | --- | --- |
| `yv12test.c` | какие дескрипторы dma-buf PowerVR принимает: целый кадр, отдельную плоскость, разные раскладки YUV | `gcc -o yv12test yv12test.c -lEGL -lGLESv2 -ldrm` |
| `imgtest.c` | создаётся ли образ EGL из дескриптора вообще | то же |
| `bindtest.c` | зависит ли привязка образа к текстуре от ширины кадра | то же |
| `sandtest.c` | переживает ли драйвер окружение без андроидной части (как песочница Firefox) | `gcc -o sandtest sandtest.c -lva -lva-drm` |

`sandtest` запускать так — это воспроизводит условия процесса декодирования
Firefox, который заперт в пустом каталоге:

    unshare -m sh -c 'mount -t tmpfs none /system; mount -t tmpfs none /vendor;
                      LIBVA_DRIVER_NAME=pvr ./sandtest'

Должен быть честный отказ `resource allocation failed` и живой процесс. Если
вместо этого `Segmentation fault` — вернулась поломка, разобранная в журнале
работ за 2026-09-17 19:45.

Итоги проб записаны там же: записи 19:30 (что принимает PowerVR) и 19:45
(почему падал процесс декодирования).
