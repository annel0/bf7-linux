# Пробы к камере BF7

Запускать на телефоне. Требуют `CONFIG_I2C_CHARDEV=y` (включён 2026-09-17).
Сборка на месте: `gcc -O1 -o проба проба.c`.

| Проба | Что делает |
| --- | --- |
| `camalive2.c` | просит ядро подобрать драйвер сенсора и проверить живость. **Порядок обязателен**: сперва `SET_DRIVER` (3107), потом `CHECK_IS_ALIVE` (3108) |
| `camstream.c` | поднимает сенсор и запускает поток кадров, потом читает счётчик кадров по шине |
| `i2cscan.c` | кто отзывается на шине |
| `i2cread.c` | прочитать байты с нулевого регистра |
| `i2creg.c` | прочитать байты **с заданного регистра** — коды опознания лежат в глубине |
| `eedump.c` | дамп EEPROM модуля камеры |
| `ctrls.c` | перечислить ручки `/dev/video0` так, как их видит обычная программа (`VIDIOC_QUERYCTRL`) — проверка, что заплата к v4l2loopback на месте |
| `vread.c` | читает `/dev/video0` и печатает распределение промежутков между кадрами и скачки яркости. **Мерить только этим, не питоном**: питон показывает свои задержки сборщика мусора как провалы потока |
| `ispreg.c` | чтение и запись регистров ISP через `/dev/camera-isp`; режим `diff` показывает, что меняется само |

## Карта железа

| Гнездо | Микросхема | Шина | Адрес сенсора | Ещё на шине |
| --- | --- | --- | --- | --- |
| 0, главная | Samsung S5K3L6 | `i2c-2` | 0x10 (код 0x30C6 в регистре 0x0000) | EEPROM 0x50, автофокус 0x0C |
| 1, передняя | GalaxyCore GC05A2 | `i2c-4` | 0x37 (код 0x05A2 в регистре 0x03f0) | — |

## Питание

Сенсор отвечает только под питанием. Раньше приходилось ловить окно в 25 мс;
теперь есть переключатель, который питание **удерживает**:

    echo "0 on"  > /proc/driver/camsensor_power   # главное гнездо
    echo "1 on"  > /proc/driver/camsensor_power   # переднее
    cat          /proc/driver/camsensor_power     # что держим
    echo "0 off" > /proc/driver/camsensor_power

Там же ручки для перебора догадок без пересборки ядра:

    echo "0 mclk 1 1"       # включить мультиплексор camtg1_sel, 24 МГц
    echo "0 pin PDN 1"      # поднять ножку PDN
    echo "0 pin DVDD 1100"  # цифровое питание 1,1 В

**Пока гнездо под удержанием, не запускать пробы, которые сами дёргают
питание** (`camalive2`, `camstream`): их выключение опустит сброс и погасит
MCLK, а регуляторы останутся включёнными по счётчику — мерить будете
половинчатое состояние, не зная об этом.

## Как снять поток

    ./camstream 0 0       # гнездо 0, сценарий 0 (предпросмотр)

Узел `/dev/kd_camera_hw` проба держит открытым нарочно: на закрытии драйвер
гасит такты и сбрасывает ножки. Признак живого потока — растущий счётчик
кадров (регистр 0x0005).

## Регистры ISP

Смещения считаются от `0x15000000`:

    0x04000  CAM_A      0x06000  CAM_B
    0x40000  seninf     0x50000  CAMSV

    ./ispreg r 0x40000 8            # прочитать
    ./ispreg diff 0x40000 0x44000   # что шевелится само

Приёмник seninf сейчас выключен — у MediaTek его настраивает
пользовательская часть (`libcam.halsensor.so`), см. журнал за 21:40.
